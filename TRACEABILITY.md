# Control and Architecture Traceability

This index connects conceptual architecture components to normative controls, profiles, machine contracts, walkthrough evidence, tests, and external enforcement. Each control range below includes controls `001`, `002`, and `003` in that domain; the canonical requirements remain in [`controls/control-catalog.yaml`](controls/control-catalog.yaml). Repository tests cover only the checks implemented by this offline kit. They do not imply that every requirement in a control range is automated; consult each control's `verification` and `external_dependencies` fields for the authoritative boundary.

## Diagram-to-Implementation Boundary

The PNG diagrams are conceptual reference views. The table below identifies what this repository implements and what must remain external.

| Diagram component | Repository artifact | Status |
|---|---|---|
| Customer systems and security data sources | Ingestion controls and evidence manifests | Conceptual source; external system |
| Ingestion and normalization | `GASO-ING-*`, source metadata guidance | Contract and checks only; external pipeline |
| Context, retrieval, RAG, and memory | `GASO-TEN-*`, threat model, scope validator | Scope records and offline comparison only; external retrieval enforcement |
| Agentic workflow or orchestration | Agent cards, recommendations, assurance records | Artifact contracts only; no agent runtime or LLM |
| AI assurance or agent judges | `GASO-ASR-*`, assurance-result schema | Non-authoritative result validation only |
| Policy Decision Point | Reference policy and deterministic evaluator | Offline reference evaluation; production PDP external |
| Human and customer approval | `GASO-APR-*`, approval records | Record/digest validation; identity and authority external |
| Policy Enforcement Point and tool gateway | Tool contracts and validate-only requests | Not implemented; external enforcement required |
| Evidence and case management | `GASO-EVD-*`, manifest and lineage validation | Metadata validation only; evidence custody external |
| Audit and replay | Hash-chain verification and deterministic replay | Offline fixture verification; durable production storage external |
| Agent governance and identity plane | `GASO-GOV-*`, `GASO-IDN-*`, agent cards | Governance contracts only; identity lifecycle external |
| Fleet operations | `GASO-FLT-*`, release and recall records | Record validation only; build/deploy/rollback external |

Passing repository tests establishes conformance of supplied synthetic artifacts to these contracts. It does not establish production enforcement, compliance, factual correctness, or forensic validity.
